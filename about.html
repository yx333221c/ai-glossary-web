关于本站与译名规范

这一页说明三件事：本站能查到什么、为什么这样译、检索为什么会把某条排在前面。 重点是统一译名——同一概念在中英文技术写作里往往有两三种流通写法， 本站只选一种，并把不采用的写法明说出来，方便你遇到时改掉而不是继续混用。

这个站是什么

纯静态，无构建，无网络请求

一本 AI 术语中英对照词典，形态是几个 HTML 文件加两个 JS 文件加一份数据。 没有框架、没有打包、没有后端、不读任何 CDN，整个目录拷进 U 盘也能用—— 直接双击 index.html 就能在 file:// 下离线打开 （数据是以脚本形式随页面加载的，不是 fetch 回来的 JSON，所以不受浏览器本地跨域限制影响）。

只有两个入口：

  • 浏览：按分类列出全部条目，可按分类、拼音首字母筛选，可切列表 / 卡片视图。
  • 搜索：一个输入框，输入即时出结果，按关联程度排序，可显示命中原因。

每个条目都能点进 term.html?id=… 看详情：机制说明、不采用译名、相关术语。 顶栏的搜索框在任意页都可用——回车时它先看一眼结果：若只命中一条，或第一名分数达标而第二名明显落后， 就直接跳到那条详情页，否则把查询交给搜索页让你自己挑。

能查到什么：数据字段

一条术语 = 一个对象

数据是一组扁平对象，字段不多但各有分工：en 与 zh 是名字， def 与 long 是内容，avoid、aka、related 是关系， cat、level、tags 是筛选维度，pinyin、py1 是为检索准备的辅助索引键。 下表最后一列写明该字段在打分时扮演的角色，方便你判断「为什么搜这个词能搜到它」。

字段含义在检索里的角色
id稳定标识符，kebab-case，如 kv-cache、kl-divergence；详情页 URL 与 related 都靠它引用完全等于查询词时给高分（idExact）；前缀 / 包含命中走通用分支，并被截到 idHas + 20 以内
en英文原词，站内统一写法（含斜杠分隔的并列形式，如 query / key / value）权重最高的字段之一：精确、前缀、词首、包含四种命中方式
zh本站统一中文译名，一个概念只此一个与 en 同级：按去空格后的紧凑形式比较
aka别名、常见缩写、同义写法数组，如 ["跳跃连接", "skip connection"]独立加分项（精确 akaExact > 前缀 > 包含）
pinyin中文名的拼音，按音节写（可空格分隔，也可连写），如 jian zhi huan cun。这一项是人工填写的支持打 qianru 找到「嵌入」；引擎会切音节并据此推出全拼串 pyFull
py1拼音首字母串，如 zyl（注意力）、jzhc（键值缓存）；索引时由 pinyin 自动派生，数据里写了也会被覆盖与全拼分开计分，两字母以上才参与匹配；派生依赖引擎内置的音节表，音节切不开时整段退化处理
cat分类键，对应 AI.CATEGORIES（数学与信息论、神经网络与架构……）分类名本身也可被搜到（权重很低）
level难度：basic 入门 / core 核心 / advanced 进阶主要用作筛选；分数相同时作为次级排序依据（进阶更靠前）
def一句话释义可被搜到（defHas），这是「搜释义词也能命中」的来源
long机制说明与适用边界的长文权重比 def 更低，只作兜底
avoid不采用译名数组，即本页对照表「不采用」那一列不参与检索打分，只在详情页提示
related相关术语的 id 数组间接命中：查询词命中了它指向的条目名时给少量加分（有上限）
tags标签数组，如 ["信息论", "优化"]弱匹配（tagHas），适合按主题粗筛
src来源标记，"glossary" 表示该条译名取自参考术语表不参与打分，只用于说明数据边界（见下文）

译名规则

写作时按这五条办
  1. 同一概念全站只用一个中文译名。 首次出现写「中文（English）」的形式，例如「键值缓存（KV cache）」；之后再提只用中文，不反复夹英文。 确实必须保留英文原词的，用 <abbr> 而不是把它塞进正文当译名。
  2. 「不采用译名」是已经流通但本站不采用的写法。 它们不是错字，而是会造成歧义或信息丢失的译法（「KL 距离」假装它对称，「代理」会和网络代理混，「步长」和 learning-rate schedule 里的 step 冲突）。 遇到请改成统一译名，需要时加一句说明，不要两个译名并列混用。
  3. 缩写首次出现必须展开。 RLHF、RAG、DPO、KV cache 这类缩写，第一次写出来时给全称： 「基于人类反馈的强化学习（RLHF）」；展开后同一段落内可以直接用缩写， 但跨模块 / 跨页要重新展开——读者未必按顺序读下来。
  4. 不自造缩写。 不许出现「注」「预注」这种只在本文档内部自洽的简称。社区已经通用的缩写（PPL、CoT）可以按第 3 条展开后使用。
  5. 有争议的概念并列标注英文原词，并明确写出争议点。 目前两个：「涌现能力（emergent ability）」——是否真的存在突变式的「涌现」，取决于你用什么度量，尚无定论； 「对齐（alignment）」——中文技术圈常与「一致性（consistency）」混用，本站 alignment 一律译「对齐」， 而「校准（calibration）」是另一个概念，指置信度是否与正确率相符，不要与对齐混。

cross-entropy交叉熵—按真实分布 p 评分却用 q 编码时的总平均码长，等于信息熵加 KL 散度；分类任务的默认损失。

gradient梯度—损失上升最快的方向，负梯度才是下降方向，且这个说法只在欧氏度量与无穷小步长的邻域内成立。
learning rate学习率步长每次沿负梯度方向挪多远。「步长」只在完全不涉及调度策略时才勉强可用。
backpropagation反向传播BP按计算图从输出回推每个参数该负多少责任。BP 是典型自造缩写，正文不出现。
activation function激活函数激励函数给网络加入非线性的逐元素运算。「激励」是控制论里的说法。
receptive field感受野视野输出位置能看到多少输入范围。「视野」会被理解成整体可见范围，与逐层的计算无关。
attention注意力关注机制按相关性为上下文各部分动态分配加权。「机制」二字只在首次引入时用，之后叫「注意力」。
query / key / value查询 / 键 / 值Q/K/V（正文首次不缩写）想找什么 / 用来被比对的名片（是连续打分，不是检索命中）/ 比对后取走的内容。
permutation equivariant排列等变排列不变输入行顺序变了，输出行跟着变同样的顺序，但每行内容不变。「排列不变」是池化才有的性质，别混。
feed-forward network前馈网络FFN（首次不缩写）、全连接层（泛用）逐位置的两层全连接，在注意力之后做非线性加工。
BatchNorm批归一化BN沿 batch 维对每个特征做标准化，因此推理时依赖已积累的运行统计量。
LayerNorm层归一化LN（首次不缩写）对每个样本自己的特征维度做标准化，与 batch 无关，所以序列模型用它。
pre-LN / post-LN前接式 / 后接式—指归一化放在子层之前还是之后。孰优孰劣本站标为争议：训练稳定性与最终性能结论并不一致。
positional encoding位置编码位置嵌入把「第几个」的信息注入词元表示。「嵌入」专指 embedding，不要与它混用。
RoPE旋转位置编码—用旋转角度表示相对位置的编码方案，天然对长度外推友好一些（但仍然会退化）。
residual connection残差连接跳跃连接把输入直接加到输出上，保住梯度通路。「跳跃」听起来像可以绕过计算，实际是相加。
pretraining预训练预学习在海量无标注数据上做下一词元预测。「预学习」会被当成「先学一点」。
scaling law规模定律缩放律损失随参数量 / 数据量 / 算力呈幂律下降的经验规律。「缩放」容易和 resize 混。
emergent ability涌现能力（emergent ability）—争议：规模跨过某阈值后才出现的能力。是否真有「突变」高度依赖评测指标是离散还是连续，本站并列保留英文原词。
fine-tuning微调精调在特定数据上继续训练已训好的模型。「精调」暗示精度提升，但微调也常带来退化。
alignment对齐（alignment）一致性争议：使模型行为符合人类意图与价值。中文常与 consistency（一致性）混用，本站一律译「对齐」。
calibration校准—报出的置信度与实际正确率是否相符。与 alignment 是两个不同概念，别混。
RLHF基于人类反馈的强化学习（RLHF）—SFT → 奖励模型 → 策略优化的三段后训练流程。首次必须展开。
reward model奖励模型RM（首次不缩写）、打分器学习人类偏好、给回答打分的模型；它给出的分数只在同一批比较里有意义。
hallucination幻觉胡说八道（口语可用，正文用「幻觉」）生成流畅但与事实或上下文不符的内容，包括与给定材料不符。
temperature温度—采样前对未归一化得分的缩放系数，控制分布的平坦程度；它不改变模型学到的东西。
logit未归一化得分logits（裸用）softmax 之前的实数分数，本身不是概率。
sampling采样抽样按概率分布挑下一个词元的过程。「抽样」在统计里另指取样。
top-p / nucleus核采样—只保留累计概率达到 p 的最小词元集合，再在其中重新归一化。
context window上下文窗口语境长度一次推理能「看到」的词元上限。它是窗口，不是长度指标。
KV cache键值缓存—复用历史词元的键 / 值以避免重复计算。省算力但不省内存，显存占用随已生成词元数线性增长。
inference推理推断用训好的模型生成输出。「推断」易与逻辑推断混，尤其在被用来翻译 reasoning 时。
multimodal多模态—同一模型处理文本 + 图像等多种输入形态。「跨模态」指不同形态之间的迁移，别混。
CLIP图文对比模型—图像与文本各一个编码器，训练时配对拉近、不配对推开，使两者落进同一空间比方向。
patch图像块方块、图像块词元ViT 把图像切成的固定小块。本站不自造「图像块词元」这种复合词，需要时在正文说明它充当词元。
InfoNCEInfoNCE（保留原词）—对比学习的损失：把配对样本的相似度从一批负样本里「考」出来。译名反而丢信息，故保留。
zero-shot classification零样本分类—该任务一个标注都不给、不加分类头，只靠候选文本描述来分类。它不等于「从没见过这个概念」。
vector quantization向量量化VQ（首次不缩写）把连续向量硬映射到一本有限码本上，从而让图像也能被表示成离散词元。
agent智能体代理能规划、调用工具、观察结果的模型系统。「代理」与网络代理 / proxy 撞车。
tool use / function calling工具调用函数调用（保留给代码语境）模型输出结构化请求让外部执行。「函数调用」留给真正的编程语境。
RAG检索增强生成（RAG）—先检索资料再让模型基于资料作答。首次必须展开；它缓解但不消除幻觉。
benchmark基准测试跑分标准化任务集，用于横向比较。「跑分」把「是否被训过」这层信息抹掉了。
saturation（基准）饱和—模型分数逼近上限导致区分度消失，此后比较不再有信息量。括号表示主语是基准。
jailbreak越狱破甲用特殊输入绕过安全限制。「破甲」是游戏黑话。
prompt injection提示注入提示词注入（冗长）、间接注入（除非强调来源）把指令藏进被处理的数据里劫持模型。与越狱的区别在于指令来自外部数据而非用户本人。
red teaming红队测试—主动攻击式地寻找失效模式；产出的是攻击面清单，不是通过率。
scalable oversight可扩展监督—如何用较弱的人监督较强的模型，包含分工、抽检、委托等路线。

搜索是怎么排序的

权重来自 AI.WEIGHTS，下表由脚本实时读取

检索内核先把查询串切成两类词：主查询词（按空白与 ,，、;；/| 切分）和 二字滑窗词（中文串长度超过 2 时自动补出，用来让「注意力机制」也能召回「注意力」）。 然后对每个词逐字段打分、把该条术语的各字段得分相加，再对所有词求和。字段倾向大致是这条阶梯： 英文名精确 = 中文名精确 > 标识符精确 > 别名 > 拼音全拼 > 拼音首字母 > 各类前缀 / 词首 > 包含 > 释义命中 > 标签 / 分类 > 关联术语命中。 名字命中永远高于正文命中：搜「词元」应该先看词条本身，而不是那些释义里提到词元的条目。

但真正决定前排顺序的不只是上面的加法分数，还有一条命中层级（tier）： 内核同时记录这次命中有多「正面」——tier 3 是某个名称字段完全等于查询词，tier 2 是名称前缀命中， tier 1 是名称子串命中，tier 0 是只在释义 / 标签 / 分类 / 关联术语里撞到。 排序时先比 tier 再比分数，并且分数还会乘以 1 + 0.6 × tier。 这一层是为了防止「名字里带这几个字」的长条目把「就叫这个名字」的条目挤下去： 打「上下文」，上下文窗口与上下文学习会稳定排在只在释义里撞到该词的概念前面。

另有三条规则值得单独说明。其一，多词查询要求全部命中才排得高： 每有一个主查询词完全没命中，整条结果的总分就乘以一次惩罚系数（下表 missFactor）， 两个词都没命中就是它的平方——所以部分相关仍会出现，但会被压到后面，不会像某些引擎那样直接丢弃； 二字滑窗词不参与这个惩罚，它们只以四成权重加分，避免把一个长名字拆碎误判。 其二，查询词拼起来正好等于完整条目名时另有加成（phraseBonus），并把层级直接抬到最高。 其三，同 tier 同分时按「进阶 > 核心 > 入门 → 中文名更短 → 英文字典序」稳定排序。 页面上那条百分比是把最终分数除以最高分换算的，只表示「与第一名相比有多相关」，不是绝对匹配度。

数据来源与边界

核心 55 条译名参考自另一项目 ai-principles-web 的术语表 （docs/glossary.md）。那个项目对本站只作参考，不运行、不修改； 本页对照表里的译名与「不采用」写法与它保持一致，其余条目与全部数据字段为本站补充。 数据本身是随页面加载的脚本文件（data/*.js），没有构建步骤，改完刷新即可生效。

关于释义的可靠性。 def 与 long 两个字段是为本项目重写的，力求准确、并刻意多写了边界与反面提醒 （例如「困惑度不等于复杂度」「零样本分类不等于从没见过这个概念」），但它不能替代论文与教材。 它是查「这个词该译成什么、大致指什么」的对照工具，不是可引用的定义出处。 前沿且存在争议的概念——涌现能力（emergent ability）、对齐（alignment）、pre-LN / post-LN 孰优——本页已明确标出「争议」， 请把它当成「此处尚无共识」的信号，而不是一个结论。 本站不给出具体论文页码或引文编号：条目少、更新快，写了反而容易过期或写错。

局限与可改进

已知的，不是将来才有的
  • 拼音只覆盖中文名字段。能搜拼音靠的是每条里的 pinyin， 引擎在索引时切音节、派生出全拼 pyFull 与首字母 py1（数据里手写的 py1 会被派生值覆盖）； 纯英文名（Transformer、Softmax 等）没有拼音，用英文名本身兜底，所以它们的检索路径就是英文名。 释义与长文里的中文没有拼音化，所以打全拼搜不到「只出现在释义里的词」，得改用汉字。 首字母还有天然碰撞：打 cy 首先出来的是「采样」，「词元」排在它后面——两者首字母相同， 碰撞只能靠多打几个字母或改搜汉字来区分。
  • related 是悬空引用的高发地。内核按 id 解析，指向不存在的 id 时不报错也不提示， 只是相关推荐与「被引用」安静地少几项。当前已加载的分片内部引用全部可解析，但数据一旦拆成多个文件分片， 漏加载或拼错一处就会静默降级；新增分片时应当补一个断链检查，而不是靠人眼核对。
  • 没有全文索引，只有线性扫描。每次检索把所有条目逐个打分，当前条目量下是毫秒级，但条目上到几千以后必须换倒排索引； 中文二字滑窗本身也可能带来噪声命中。
  • 搜索框没有离线建议下拉。输入时要按 / 或到搜索页才好用； 顶栏那个框只支持回车跳转，不做候选提示。
  • 拼写容错很弱。编辑距离兜底只在其它字段全部失手、且查询词不短于 4 个字符时才生效，阈值固定为 1； 手滑打错两个字母，或者中文输入法串了行，就是零结果。
  • 无中文分词与词形还原。英文 token 与 tokenization 只靠子串与前缀联系， 复数、动词化形式没有归一化，同义词也只靠 aka 与 tags 里有没有人工写进去。
  • 术语覆盖面偏窄。目前集中在语言模型与其周边，计算机视觉细节、强化学习、语音、传统机器学习只点到为止； 没有版本与时间信息，也无法反映某个译名在 2024 年之后是否已经改朝换代。

数据是纯文本，欢迎指出某条统一译名或禁用译名的不妥。
