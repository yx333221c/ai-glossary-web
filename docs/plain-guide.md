# 白话版（plain）写作规范

面向零基础读者，给每条术语补一段 `plain` 字段。这是全站唯一新增字段，其余字段一律不动。

## 三段结构，各管一件事

| 字段 | 读者 | 作用 |
|---|---|---|
| `def` | 已经知道这个词，想确认译名 | 一句话，准确即可 |
| `plain` | **完全不懂的新手** | 讲明白它到底在说什么 |
| `long` | 想深入的人 | 机制、边界、常见误解 |

`plain` 不是 `long` 的缩写，也不是换一批同义词重写一遍。它要回答的是「这玩意到底是个什么东西」，靠的是类比、具体场景和把省略的步骤补上。

## 检查项

`node tools/lint-prose.js --strict` 会跑全部检查。分两级：**硬性**不过就报错退出，**建议**只提示、由人判断。

### 硬性（会失败）

1. **长度 150–420 字**（去掉空白后统计）。太短讲不清，太长没人读。
2. **不能拿 `def` 和 `long` 里没有的具体事实来充数**。不许新增阿拉伯数字、年份、《》作品名、人名。类比可以用日常事物（水果、地图、菜谱、邮局），但日常事物不是事实断言。这条由 `tools/mutate-facts.js` 反向验证过：往现成条目里注入「3.5」「2016」「《…》」，lint 必须变红。
3. **不能和 `long` 高度重合**（字符二元组重合度 > 72% 判失败），否则等于没写白话版。
4. **不能以指代开头**（「这个概念」「该技术」）。详情页可能被人直接分享，脱离上下文也要读得通。

### 建议（提示，人来定）

5. **要有类比或举例**：就像 / 好比 / 比如 / 打个比方 / 想象 / 相当于 / 可以这样理解 / 简单说 / 生活中…… 至少一个。
   之所以不是硬性：正则能认出带标记的类比，认不出**不带标记**的。曾有四条被判"没有类比"，实际开头就是"像训一只小狗""把一兜混色弹珠倒在桌上""让实习生先打草稿、老板核对"。把它设成硬失败，只会逼人塞一句假的"就像"来过关。
6. **句子要短**：最长句 ≤ 60 字，平均 ≤ 42 字。
7. **别比 `long` 更依赖英文**：白话版英文字母占比超过 18%，或高于该条 `long`，说明还是在讲行话。
8. **中文数量说法**（几十、上百、三倍、百分之几）若原文没有会提示。多数情况它只是类比的道具（"一个班几十号学生"），不是事实断言，所以不硬拦；但看到提示要自己确认一遍。

## 去 AI 味

现有文本实测出来的问题不是「赋能」那类空话（几乎没有），而是**句式单调**。所以下面这些在 `plain` 里都有额度：

| 模式 | plain 上限 | 为什么 |
|---|---|---|
| 破折号 `——` | 1 次 | 用多了就是靠破折号制造悬念 |
| `因此` `从而` `因而` `故而` | 1 次 | 默认用文言连接词，读着像论文摘要 |
| `不是 X 而是 Y` | 1 次 | 假对比抬语气 |
| `代价是` | 1 次 | 同一个转折句式反复用 |
| `本质是` | 1 次 | 同上 |
| `标志着` `彰显` `赋能` `无缝` `闭环` `旨在` | 0 | 空话 |
| `值得注意的是` `需要注意的是` `不难发现` `众所周知` | 0 | 起跑式铺垫 |
| `随着…` / `在当今…` 开头 | 0 | 背景套话 |
| 三个「的」连用（`A的B的C的D`） | 0 | 长定语读不动 |
| `总而言之` `综上所述` `让我们` | 0 | 套话收尾 |

`「」` 引号**不算** AI 味，它是本站既定的术语标记约定，照常用。

还有一条工具查不出来，只能靠自觉：

- **别把句子切成一样的长度，也别让比喻撞车**。三段式排比、每句同一个句式起头，都是模板感的来源。同一分类里五条术语都用厨房打比方，单看每条都成立，连着读就露馅。`npm run metaphors`（`tools/metaphor-map.js`）会把每条的类比句抽出来按生活场景归类，专门用来看这种撞车；它只能提示，判断还是人来下。

## 三个实例

### 词元（token）

`def`：模型处理文本的最小单位，既不是「词」也不是「字」。

`plain`：打个比方，模型读句子就像我们看一串被剪碎的话，词元就是那些剪下来的小片。中文里一片常常是一个字或半个词，英文里一片短到两三个字母，也可能正好是一个常用词。同样一段话，换一种切法，剪出来的片数会差很多，所以「这篇文章有多长」在模型那里其实等于「有多少片」。片数既决定它一次能读多少内容，也决定这次对话要花多少钱。

要点：`long` 讲的是「跨语言长度不可比、决定计费」，`plain` 用「剪碎的话」把同一件事说给没接触过的人听，没有新增任何数字。

### 嵌入（embedding）

`def`：把离散对象映射成连续向量，使「相似」变成可计算的远近。

`plain`：可以这样理解：嵌入是给每个词、每段话发一串坐标，意思接近的东西，坐标就挨得近。好比把一批水果放到一张图上，苹果和梨会落在相邻的位置，离汽车很远。这样一来，「这两个说法像不像」就不用人来判断，算一下两点之间的距离或者两个箭头的夹角就有答案。要注意一点：坐标挨得近，可能是训练时特意要求的结果，也可能只是学着学着顺带形成的。这两种情况下，「近」的含义并不一样。

要点：`long` 里的「余弦还是欧氏」「目标还是副产品」都是行话，`plain` 换成「一张图上的位置」，但保留了那个真正的区分。

### 反例（不要这样写）

> 该技术本质上是一种映射手段，其核心价值在于将离散对象转化为连续表示，从而使得相似性计算成为可能——这是现代深度学习的重要基石。

问题：`本质上`、`从而`、`——`、`重要基石` 全踩线；没有类比；`其` 字开头读不通；而且它假设读者已经知道「离散对象」「连续表示」是什么。

## 怎么改一个条目

1. 打开对应的 `data/data-<分类>.js`，找到条目。
2. 读 `def`、`long`、`avoid`，想清楚这条到底在说什么。
3. 在 `def` 那行**下面**加一行 `plain: "……",`，缩进对齐其他字段（6 个空格）。
4. 跑 `node tools/lint-prose.js data-<分类>.js --strict`，只要不再报**你负责的文件**的硬性违规就行。
5. 跑 `node --check data/data-<分类>.js` 确认语法。

只改 `plain`。`id`、`en`、`zh`、`pinyin`、`cat`、`level`、`def`、`long`、`avoid`、`related`、`tags`、`src` 都不要动——它们有测试覆盖，改了会挂。
